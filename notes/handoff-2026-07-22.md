## What this project is

A book-length practitioner's guide to writing **test plans for EHR data
transformations**, using Clojure tooling, with category theory as the
reasoning language. Two audiences: Clojure/FP/CT readers learning the
healthcare domain, and healthcare-integration veterans (often Python
people) learning the theoretical structure. Monorepo: `manuscript/`
(markdown chapters, Pandoc build via `make book`) + `companion/` (Clojure
reference implementation — every manuscript listing exists there and is
tested; `make check` runs both). Private GitHub repo; the author works on
Windows, git through WSL only.

## The intellectual spine (compressed; full version in notes/design-rationale.md)

The universal-canonical-format dream fails structurally → arrows are
lenses/spans, not isomorphisms → the representations are different *kinds*
(v2 = delta/event, FHIR = sigma/state = fold of deltas, C-CDA = attested
snapshot where the signature is content) → the honest universal object is
a bitemporal event log, formats are views/ingestions → therefore
correctness is **observational**: f is correct for query q iff q∘f =
q-source; the recipient's purpose set IS the spec; correctness is a
lattice (correct-for-A, incorrect-for-B simultaneously); the residue
(info no in-scope query observes) is an enumerated, signed artifact.
Book structure: Part I problem, Part II method (spine), Part III
structure, Part IV dated reference entries, back matter incl. test-plan
templates (§94) and failure-mode index.

## The working method (converged; refinements since last handoff marked •)

**Division of labor.** Judgment-heavy prose is drafted interactively in
chat, placed by the author, then a **Claude Code integration prompt**
clears mechanical debt. Bounded mechanical assembly goes to **Cowork**
(ch 43 precedent: works well, but any entry not traceable to the stated
source must be adjudicated in chat like a mid-session Code draft — the
ch 42 rule, now twice applied). Commits are ALWAYS manual, by the author,
through WSL. Cadence: one draft → one integration session → one commit;
paired landings (a chat draft + a parallel Cowork assembly) may share one
integration session and one commit when the shared mechanical files
(register, glossary, status table) can't split cleanly.

**Integration prompt conventions.** State what's placed and approved
(do-not-redraft); enumerate tasks; acceptance checks including
`clojure -X:test` green, `make book` spot-checks with specific phrases,
no notes/ leakage, and a `git diff --stat` scope allow-list; end with
report-and-stop, no git writes. • Supply verbatim text in the prompt for
any prose the session must write (glossary entries, entry patches,
single-sentence reconciliations) — Code inserts, never composes, which
collapses the review burden. • When a placed chapter appears in the diff
from the author's placement, require Code to confirm it added zero hunks
to it, not merely that the file is in the allow-list. • Include at least
one check that greps the *built* output, not just the source — that is
how the citeproc gap was caught. • Phrase spot-checks must use
newline-flattened matching; the ~75-col hard wrap splits phrases across
lines and naive grep false-negatives.

**Hard-learned lessons (cumulative).** (1) Sentinel paste blocks are a
manual single point of failure — prefer content already on disk; chat
drafts are delivered as repo-ready files. (2) A wholesale section paste
once deleted committed reference entries — check entry counts after
placements. (3) The author's commit state drifts from belief — start
planning sessions by having the author paste `git status`. (4) Chapter
HTML comments record sync obligations; leave them after payment (register
is source of truth). (5) The pack is how chat sees the repo; locate by
grep, not line numbers. • (6) Packs go stale: an uploaded pack once
lacked an entire session's edits, mimicking clone drift — before acting
on a pack, verify it contains a distinctive phrase from the most recent
work and the expected register rows; if it doesn't, ask for a re-pack
before diagnosing anything worse. (7) Prose-touching agent output gets
read closely field-by-field (43's NIST entry); mechanical output gets
verified against the pack, not trusted from the report.

**Chapter drafting conventions** (enforced; see AUTHORS-GUIDE): thesis
blockquotes are committed content; introduce-twice for every CT term and
every healthcare term — • note that reading order, not drafting order,
determines who owes an introduction (ch 11, drafted late but read first,
owed the introductions for retraction, coproduct, colimit, Z-segments,
extensions, open templates); no pseudocode (ADR-0007) — a listing creates
a companion obligation in the chapter's HTML comment, and a Part I
chapter that needs no listings should stay that way; glossary/acronyms at
first use; Part IV entries only via the template; new sharp claims get
register rows; prose over bullets.
