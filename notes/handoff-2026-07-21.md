## What this project is

A book-length practitioner's guide to writing **test plans for EHR data
transformations**, using Clojure tooling, with category theory as the
reasoning language. Two audiences: Clojure/FP/CT readers learning the
healthcare domain, and healthcare-integration veterans (often Python
people) learning the theoretical structure. Monorepo: `manuscript/`
(markdown chapters, Pandoc build via `make book`) + `companion/` (Clojure
reference implementation — every manuscript listing exists there and is
tested; `make check` runs both). Private GitHub repo; the author works on
Windows, git through WSL only.

## The intellectual spine (compressed; full version in notes/design-rationale.md)

The universal-canonical-format dream fails structurally → arrows are
lenses/spans, not isomorphisms → the representations are different *kinds*
(v2 = delta/event, FHIR = sigma/state = fold of deltas, C-CDA = attested
snapshot where the signature is content) → the honest universal object is
a bitemporal event log, formats are views/ingestions → therefore
correctness is **observational**: f is correct for query q iff q∘f =
q-source; the recipient's purpose set IS the spec; correctness is a
lattice (correct-for-A, incorrect-for-B simultaneously); the residue
(info no in-scope query observes) is an enumerated, signed artifact.
Book structure: Part I problem, Part II method (spine), Part III
structure, Part IV dated reference entries, back matter incl. test-plan
templates (§94, drafted) and failure-mode index.

## The working method (this is the part that took longest to converge)

**Division of labor.** Judgment-heavy prose (chapters, sharp claims) is
drafted interactively in chat, pasted/placed by the author, then a
**Claude Code integration prompt** clears the mechanical debt: back-matter
sync, register flips, status rows, companion obligations, acceptance
checks. Bounded mechanical assembly goes to **Cowork**. Commits are
ALWAYS manual, by the author, through WSL — no agent ever commits.
Cadence: **one draft → one integration session → one commit**. Do not
batch drafts; integration debt compounds and diff review stops happening.

**Integration prompt conventions** (follow the pattern of prior ones):
state what's placed and approved (do-not-redraft); enumerate tasks;
explicit acceptance checks including `clojure -X:test` green, `make book`
spot-checks with specific phrases, no notes/ leakage, and a `git diff
--stat` scope allow-list; end with report-and-stop, no git writes.
Sanction any exceptional git operation explicitly (precedent: one
index-only `git rm --cached`). Read the report's scope check and any
prose-touching edit closely; skim the rest.

**Hard-learned lessons.** (1) Sentinel paste blocks (`<<<X ... X>>>`) are
a manual single point of failure — the author once ran a prompt with the
block unfilled; Code correctly stopped and asked. Prefer content already
on disk. (2) A wholesale section paste once deleted three committed
reference entries; recovery was `git show HEAD:path`. Check entry counts
after placements. (3) The author's commit state drifts from belief —
start planning sessions by having the author paste `git status`. (4)
Chapter HTML comments record sync obligations; convention is to leave
them after payment (register is source of truth). (5) The pack file
(`make pack` → uploaded to the Project) is how chat sees the repo;
line numbers shift between packs — locate by grep, not memory.

**Chapter drafting conventions** (enforced; see AUTHORS-GUIDE): thesis
blockquotes are committed content — honor them; introduce-twice for every
CT term and every healthcare term; no pseudocode (ADR-0007) — a listing
creates a companion obligation recorded in the chapter's HTML comment;
glossary/acronyms updated at first use; Part IV entries only via the
template (kind list is an open vocabulary — precedent: modeling
framework, workflow composition, access machinery, observation language);
new sharp claims get register rows with destinations; prose over bullets,
tables only where content demands.
